
# Rollenmatrix

## Zweck

Die Rollenmatrix macht sichtbar, wer eine Governance-Routine betreibt, wer beiträgt, wer reviewed und wer entscheidet. Sie ersetzt keine formale Rollenfreigabe durch das Management.

## Trigger

Nutzen bei unklaren Zuständigkeiten, neuen Anforderungen, ISMS-/NIS2-/BCMS-Aufbau, Evidence-Pack-Arbeit oder Management Review-Vorbereitung.

## Nutzer

- ISB/CISO oder Security-Verantwortliche
- Prozess- und Service Owner
- Management Review-Facilitator
- interne Revision oder Qualitätsfunktion als Reviewer

## Input

- Scope
- relevante Anforderungen oder Registereinträge
- bestehende Rollen/Gremien
- betroffene Prozesse oder Services
- offene Entscheidungen

## Ablauf

1. Routine oder Artefakt benennen.
2. menschlichen Owner festlegen oder als offene Entscheidung markieren.
3. Beitragende und Reviewer ergänzen.
4. Entscheidungsrolle und Eskalationsweg markieren.
5. Evidenzoutput der Rolle festlegen.
6. Konflikte und Überlastung sichtbar machen.

|  |  |  |  |  |  |  |  |  |

## Output

- Rollen- und Verantwortungsentwurf
- offene Owner-Entscheidungen
- Eskalations- und Reviewpunkte
- Input für Management Decision Brief

## Evidenz

Als Evidenz entstehen Rollenmatrix, Freigaben/Änderungshistorie, Reviewnotiz und ggf. Decision Log.

## Grenzen

- keine Managemententscheidung automatisieren
- keine rechtliche Verantwortungsbewertung vorgeben
- keine personenbezogenen Daten in öffentliche Beispiele eintragen
- keine Rollen ohne reale Belastbarkeit als final markieren

## Review

Review bei Rollenwechsel, Scope-Änderung, neuen Anforderungen, Incidents, Audit Findings oder mindestens halbjährlich.
