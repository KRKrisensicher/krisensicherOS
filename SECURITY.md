# Security Policy

## Project boundaries

krisensicherOS is an open-source operating repo for security governance, NIS2 readiness, ISMS, BCMS, crisis readiness, and AI-assisted governance.

The contents are aids. They do not replace legal review, data protection advice, security review, certification, or a management decision.

## Security and confidentiality rules

Please do not publish confidential information in issues, pull requests, examples, or discussions.

Do not submit:

- personal data,
- customer data,
- internal security incidents with identifiable details,
- credentials, tokens, or secrets,
- confidential contracts,
- licensed standard texts,
- non-public vulnerability information without an agreed notification path.

## Handling vulnerabilities

If you find a vulnerability in repo artifacts, example workflows, templates, or agent profiles:

1. Describe the problem without confidential details.
2. Explain which artifact is affected.
3. Name possible impacts.
4. Suggest a safe correction, if possible.

Until an official contact path is named in the public repository, real confidential vulnerability details should not be posted publicly.

## Security gates for contributions

Contributions should check:

- no secrets,
- no real personal or organizational data,
- no confidential contract content,
- no copies of standard texts,
- no false assurance through compliance or certification claims,
- clear human-in-the-loop points,
- safe examples with fictional data.

## Supported versions

Before the first public release, there are no stable supported versions yet. Changes before v1.0 may be structural.
