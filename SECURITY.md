
# Security Policy

## Projektgrenzen

krisensicherOS ist ein Open-Source-Betriebsrepo für Security Governance, NIS2-Readiness, ISMS, BCMS, Krisenfähigkeit und AI-assisted Governance.

Die Inhalte sind Hilfsmittel. Sie ersetzen keine rechtliche Prüfung, Datenschutzberatung, Sicherheitsprüfung, Zertifizierung oder Managemententscheidung.

## Sicherheits- und Vertraulichkeitsregeln

Bitte keine vertraulichen Informationen in Issues, Pull Requests, Beispielen oder Diskussionen veröffentlichen.

Nicht einreichen:

- personenbezogene Daten,
- Kundendaten,
- interne Sicherheitsvorfälle mit identifizierbaren Details,
- Zugangsdaten, Tokens oder Secrets,
- vertrauliche Verträge,
- lizenzpflichtige Normtexte,
- nicht öffentliche Schwachstelleninformationen ohne abgestimmten Meldeweg.

## Umgang mit Schwachstellen

Wenn du eine Schwachstelle in Repo-Artefakten, Beispiel-Workflows, Templates oder Agentenprofilen findest:

1. Beschreibe das Problem ohne vertrauliche Details.
2. Erkläre, welches Artefakt betroffen ist.
3. Benenne mögliche Auswirkungen.
4. Schlage eine sichere Korrektur vor, wenn möglich.

Bis ein offizieller Kontaktweg im öffentlichen Repository benannt ist, sollten keine realen vertraulichen Schwachstellendetails öffentlich abgelegt werden.

## Security-Gates für Beiträge

Beiträge sollten prüfen:

- keine Secrets,
- keine echten Personen- oder Organisationsdaten,
- keine vertraulichen Vertragsinhalte,
- keine Normtextkopien,
- keine Scheinsicherheit durch Konformitäts- oder Zertifizierungsclaims,
- klare Human-in-the-loop-Punkte,
- sichere Beispiele mit fiktiven Daten.

## Unterstützte Versionen

Vor dem ersten öffentlichen Release gibt es noch keine stabil unterstützten Versionen. Änderungen vor v1.0 können strukturell sein.
