# ISMS Implementation Guide: Roles, Routines, Evidence, and Reviews

## Purpose

This guide helps organizations build an information security management system as an operable way of working: with clear roles, recurring routines, management decisions, evidence flows, and reviews.

The guide supports practical work with ISO/IEC 27001 as a reference framework. It contains no standard texts, no control wording, and no certification assurance.

## Usage

Do not start with all modules at the same time. Begin with scope, roles, and risk steering. Then add operating routines, evidence, management review, and internal checks.

For a compact first pass, use:

- [`../../docs/getting-started/anwenderpfade.md`](../../docs/getting-started/anwenderpfade.md) — path “Start ISMS”.
- [`../../docs/getting-started/artefaktpakete.md`](../../docs/getting-started/artefaktpakete.md) — package “ISMS minimal start”.
- [`../../examples/fiktiver-mittelstand/isms-90-minuten-durchstich.md`](../../examples/fiktiver-mittelstand/isms-90-minuten-durchstich.md) — fictional 90-minute example.

## Implementation Logic

| Standard-aligned term | krisensicherOS implementation logic |
| --- | --- |
| Requirement | Routine / decision point |
| Control | Protective measure / way of working |
| Audit criterion | Check question / evidence trail |
| Documentation | Evidence flow |
| Responsibility | Role with decision authority |

## Reference Framework

The modules refer to ISO/IEC 27001 as a reference framework and, where relevant, add public NIS2/BSIG references. The specific interpretation, applicability, and external certification questions must be reviewed by professionally responsible persons.
