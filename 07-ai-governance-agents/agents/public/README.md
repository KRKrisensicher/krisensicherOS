# Public Target-Repo Agents

This folder contains the agent profiles that future users of krisensicherOS can adopt for their own compliance and security governance system.

## Purpose

The target-repo agents help organizations build their own agentic working model for NIS2, ISMS, BCMS, compliance register, evidence work, and management reviews.

They are not a substitute-for-advisers claim and not a responsibility machine. They structure work, prepare decisions, review artifacts, and make open points visible.

## Role Model

The role model is in:

- `role-model.md` (`role-model.md`)
- `anwender-routing.md` (`anwender-routing.md`) — reduced entry selection with a maximum of eight starting agents.

## Profile Standard

All public agent profiles follow the krisensicherOS profile standard:

- clear mandate,
- clear non-responsibility,
- input data,
- standard workflow,
- deliverables,
- success criteria,
- quality gates,
- anti-patterns,
- handoff protocol,
- Definition of Done.

## Agent Families

### 1. Steering and Operating System

- `compliance-operating-system-lead` — orchestrates the setup of the user’s own compliance and security governance system.
- `agent-quality-and-safety-reviewer` — reviews agent outputs for boundaries, false assurance, source risks, and approval risks.

### 2. Sources, Register, and Requirements

- `regulatory-source-mapper` — classifies public legal sources and regulatory references.
- `compliance-register-curator` — maintains the structure for user-owned requirements such as standards, contracts, and internal policies.
- `third-party-requirements-analyst` — translates customer/supplier requirements into reviewable governance work.
- `data-protection-interface-reviewer` — marks data protection interfaces without claiming to provide data protection advice.

### 3. Management Systems and Governance Routines

- `security-governance-architect` — builds roles, routines, decisions, and evidence flows.
- `isms-operating-model-designer` — designs a Minimum Viable ISMS as an operating model.
- `bcms-readiness-designer` — structures BCMS/crisis readiness work.
- `risk-and-obligation-prioritizer` — prioritizes requirements, risks, and measures.

### 4. Evidence, Documents, and Reviews

- `control-evidence-architect` — connects controls, routines, and evidence.
- `evidence-pack-reviewer` — reviews evidence packs for completeness, quality, and boundaries.
- `policy-and-controls-drafter` — creates drafts for policies/controls as an internal working basis.
- `management-review-facilitator` — prepares management decisions and reviews.

### 5. Readiness and Exercises

- `nis2-readiness-analyst` — prepares NIS2 gap and readiness work.
- `incident-readiness-coach` — structures incident escalation and exercise logic.

## Handoff Ground Rule

No agent solves everything alone. If an output touches technical, legal, operational, or source boundaries, it is handed off internally to the responsible agent.

Questions for humans arise only when agents cannot resolve the conflict using existing repo rules, sources, templates, and quality gates.
