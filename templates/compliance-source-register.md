# Compliance Source — Register Entry

## Purpose

This template helps user organizations structure their own compliance requirements as register entries: public sources, standard references, customer requirements, internal policies, audit findings, or insurance requirements.

It stores metadata, own summaries, mappings, evidence references, and agent usage boundaries. It does not provide legal advice and is not a binding contract interpretation.

## Trigger

Use when a new or changed requirement is to be added to the compliance register, reviewed, mapped, or made usable for agent work.

## Users

- Compliance-Register-Curator
- Regulatory Source Mapper
- information security officer/CISO or security responsible parties
- business unit or process owners
- legal or data protection review as human review, if required

## Input

- source or storage location
- type of requirement
- owner
- status and applicability
- confidentiality or license notice
- own summary
- desired agent usage

## Process

1. Capture metadata.
2. Define confidentiality, license, and permitted agent usage.
3. Describe the requirement only as an own summary or reference.
4. Map requirements to governance routines, controls, measures, and evidence.
5. Mark open interpretation, data protection, or management questions.
6. Define review frequency and responsible human role.
